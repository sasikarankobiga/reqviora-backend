# Scope and constraints

## Candidate V1

- Authenticated project workspace, manual authoring, version-safe drafts and scoped project roles.
- PDF/DOCX/TXT, typed text and consented Tamil/English voice with traceable source evidence.
- AI suggestions, clarification and explicit user review. Feature and screen selection, navigation and interaction modeling.
- Validated Blueprint, allowlisted rendering, visual editing and mock preview.
- Deterministic validation, explicit approval, immutable revisions and 19-reference handoff plus a manifest. Scoped read-only MCP and audit controls.

## Exclusions

Production customer applications, backends, customer APIs and live commercial transactions. Full native emulation, unrestricted design editing or generated-code execution, advanced real-time co-editing, subscription billing and unrestricted integrations.

## Constraints and dependencies

- Manual authoring remains available when AI consent is declined, quota is exhausted or providers fail.
- Scope uses the proposed eight-stage journey with earlier seven-stage drafts tracked for migration. Formal approval still determines the stage count.
- Keep AI/STT credentials on the backend, isolate file processing, limit input sizes/jobs, enforce project grants and omit private data from telemetry.
- Confirm provider, data residency, retention, browser and numeric service targets through the [open questions](open-questions.md).
- The five optional AI helpers in BRD Appendix D.1 remain unnumbered candidates pending scope review.

Source: BRD §§1, 7.2, 10 and Appendix D. GUIDE §§12, 20.
